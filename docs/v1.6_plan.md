## B. Claims that need re-verification before any fix (do these probes first)

### B1. License consistency (AGPL-3.0-only)
- **Claim:** licensing wording/headers inconsistent across files.
- **Verify:** `grep -rn "SPDX\|License:" *.py core/*.py` — check every shipped
  .py carries the AGPL header, README/LICENSE match (`AGPL-3.0-only`, confirmed
  at README:71 and LICENSE head). Check presets/ proprietary notice wording.
- **Fix if true:** add missing SPDX headers via script; gate = a test that every
  tracked .py contains `SPDX-License-Identifier: AGPL-3.0-only`.

### B2. Performance claims ("renders slow / should use NVENC / GPU")
- **Claim:** rendering pipeline should offload to NVENC/GPU.
- **Verify (probe):** time a full CLI render at 1080x1920@30 on this machine;
  profile where time actually goes (frames vs encode). `grep -rn nvenc core/` =
  zero hits — the audit's NVENC suggestion is *aspirational, not a regression*.
- **Decision if true:** only pursue encoder-level speedups (x264 preset tuning
  first — cheaper than an NVENC matrix) and only if encode >30% of render time.
  Record the measured split in this doc before deciding.

### B3. Error-handling / validation gaps
- **Claim:** some malformed project inputs reach the engine unvalidated.
- **Verify:** fuzz-style probe: feed `validate_project` hostile payloads (huge
  lists, wrong types, nested None) in-process; compare against current gates
  (tests/test_trust_boundary.py exists). Only fix reproducible bypasses.

### B4. Docs accuracy (QUICKSTART / release notes drift)
- **Claim:** docs reference removed/renamed flags or stale version strings.
- **Verify:** run every command line printed in docs/QUICKSTART.md and
  docs/release_v1.5_notes.md against the current CLI; diff flag lists.

   before push (Linux golden rule).
