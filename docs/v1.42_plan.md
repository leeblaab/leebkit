# LEEBKIT v1.42 — Kinetic Depth plan (advisor list, validated against v1.41)

Working doc for the v1.42 increment. Source: the advisor's two documents
(kinetic recommendations + `release_onyx_promo_v2` overlay), audited point by
point against HEAD `cd67745` (v1.41). 11 items in 4 tiers. All of it is
**additive**: new fields/kinds are opt-in, defaults byte-identical, goldens
untouched except for NEW corpus entries.

## Audit corrections baked into this plan
- `whip` + per-shot `layout:{...}` — already shipped (v1.4 C2/C6). Not in scope.
- advisor's `voice_speed` top-level field — already works (v1.41 C1).
- advisor's "strikethrough bug" claim — misdiagnosis: the title underline is
  post-fit anchored (`base_y` from the fitted size); kicker rules are
  post-fit anchored too. Item 2 PROVES this with a probe render before any fix.
- `accent_word colors` — REAL gap (item 1).

## Non-negotiable discipline (every commit)
1. Test-first: failing test, then implement, then gate green.
2. Opt-in fields/kinds; default path byte-identical → goldens stay green with
   ZERO re-baseline except new corpus entries.
3. New kinds/fields touch ALL sites in lockstep:
   schema whitelist (engine.py) + validate_project (checks.py) +
   `measure()` (metrics.py — single source of truth) + draw path
   (captions.py/engine.py) + checker branch (checks.py) + corpus entry
   (tests/golden/kinds_corpus.json).
4. Everything a pure function of `(t, seed)` — deterministic; sample renders
   must equal full renders.
5. Gate per commit: targeted test → `scripts/smoke_test.py` → golden harness
   (`scripts/golden_frames.py`; hashes-linux.json only if the linux table is in
   use) → CLI render + ffprobe A/V gate on a new-field project.
6. Local commits only. NO push until Yasser's green light after testing.

## FrameCtx change (shared by items 3-8) — coordinated sites
`FrameCtx` namedtuple (captions.py:31) gains `g` (global frame time),
`beat` (phase 0..1 at the bed BPM; None = no clock), `exit_t` / `exit_kind`
(per-caption exit clocks, precomputed in render_layer). Sites: FrameCtx def +
construction (engine.py ~806) + metrics/checks parity. All new fields default
None → existing behavior unchanged.

## TIER 2 — feel per line (the money tier)

### Item 3 — beat clock [C0]
`BED_BPM` dict in core/audio.py (pulse 120, low_drive 92, sparkle 130 — move
the literals there, single source). FrameCtx gains `beat = frac(g * bpm/60)`
when the music bed is procedural (mode none/sidechain/file → None unless
project `bpm` override given; new optional project field `bpm`). Pure function
of frame index → deterministic. Test: beat phase at known frames, determinism
across sample/full render.

### Item 4 — exit clock [C0]
Per-caption opt-in `"exit": "rise" | "blur" | "wipe" | "scale"` (schema +
validate). Exit starts at `shot_t − EXIT_RAMP` (EXIT_RAMP=0.25, metrics const),
runs to the cut: rise = drop+fade, wipe = reverse mask sweep (reuse line_wipe
math inverted), scale = shrink+fade; blur = scale-down proxy ONLY if the
per-frame gaussian cost measures <15% on the benchmark (else document as
unsupported). render_layer precomputes `exit_t/exit_kind` into FrameCtx.
Checker: an exiting caption must have settled before exit starts
(`done_at + 0.1 <= shot_t − EXIT_RAMP`) — new flag kind `exit`. Corpus entry.

### Item 5 — idle motion: breathe + color-wave [C0]
Opt-in `"idle": true` on any caption (schema + validate). Gate: only while the
caption is SETTLED (`g >= done_at` and before exit) — metrics already exposes
done_at so checker parity is by construction. breathe = ±2% scale sine (3s
period, seed-locked phase); color_wave = hue jitter on per-word tints (only
meaningful with `colors`; without it, accent↔white micro-pulse). House-rule
guard: idle counts as the line's one animated property AFTER settle — entrance
kinds unchanged. Checker flag: `idle` on a kind that never settles inside the
shot is an error. Corpus entries (breathe + color_wave).

### Item 6 — easing library [C0]
Add `ease_expo_out`, `ease_back_in`, `ease_elastic_out`, `ease_step3` to
engine.py next to ease_io/ease_o/ease_ow; extend the `e` tuple passed to
captions (coordinated: FrameCtx/e consumers in captions.py updated in the same
commit). Opt-in `"ease": "expo"|"elastic"|"steps"` on entrance kinds where it
plugs into an existing progress var (pop/pump/slam/wipe/trackin; NOT kicker —
its stagger is locked). Checker: none needed (no clock change — settle time
unchanged by easing except elastic overshoot which settles at the same ramp).
Corpus entry for one new easing.

## TIER 3 — showcase set (one commit each)

### Item 7 — sprite compositor + `slam_v2` [C0]
BENCHMARK FIRST: per-word RGBA sprite layers (translate/scale/rotate via
`Image.transform AFFINE` bilinear, alpha_composite) vs current per-frame
redraw on the kinds corpus shot; proceed only if frame cost ≤ +15%, else ship
slam_v2 with scale-only math on the existing path and document why.
`"kind": "slam_v2"` = slam entrance + squash-stretch (scaleY 0.8→1.1→1 over
SLAM_RAMP) + motion trail (2 echo pastes at decaying alpha from previous
scales, pure function of t). New kind sites ×6 + corpus entry.

### Item 8 — glitch / RGB-split [C0]
`"fx": "glitch"` opt-in field on big_word/accent_word/slam_v2 (schema +
validate). Within the entrance ramp only: R/Cyan channel offset ±(4..12)px on a
sin step function of `beat` (uses item 3 clock; falls back to seed time when
beat None); settles to zero at done_at. Cost: two extra tinted paste layers, no
gaussian. Checker: fx needs an entrance kind with a settle clock (flag if not).
Corpus entry.

### Item 9 — underline draw-on + tracking collapse [C0]
Two micro-kinds: `"kind": "rule_draw"` (a rule element that draws left→right
over POP_RAMP, width from L or measured text) and `"fx": "track_collapse"` on
accent_word/title sub-plate (tracking starts +18px, collapses to 0 over
TRACK_RAMP — reuses trackin math inverted). Sites ×6 for the kind; fx field.
Corpus entries.

## TIER 4 — audio-reactive + finish pass

### Item 10 — VO envelope + EQ bars [C0]
`"kind": "eq_bars"`: N bars (default 5, ≤7) at bottom safe margin, heights =
abs sine stack seeded per bar, amplitude modulated by the bed's beat clock;
with a project `voice` present AND a VO wav for the shot, heights mix in the
VO envelope — envelope precomputed ONCE per shot from the vo_plan wav via
stdlib `wave` module RMS windows (no numpy), cached on Engine. Deterministic
(wave bytes are deterministic given piper output; sample==full). Checker: bars
must fit safe area + settle semantics = always animating (terminal-like, no
done_at gate but must not extend past shot — it's per-shot like other kinds).
Corpus entry.

### Item 11 — file-bed beats + `--finish` encode pass [C0]
(a) BPM metadata: hand-shipped `assets/music/BPM.json` mapping the three CC0
beds (pulse/low_drive/sparkle file variants) to their measured BPM; item 3's
clock reads it for `mode:"file"` beds. No onset detection (determinism risk,
heavy deps). (b) `--finish <name>` CLI: re-encode `output/<name>.mp4` with a
final-light pass — currently just documents/locks the shipped pipeline; if any
post-fx land in 7-10 that need two passes (e.g. bloom), this flag carries them.
Ship as CLI + docs commit, ffprobe gate.
