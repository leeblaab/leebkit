# LEEBKIT v1.4 — Plan (draft for approval, 2026-11-11)

Theme: **Resolution + share formats + procedural backgrounds + templates.**
Generator foundation lands in v1.4 (approved by both internal audit and the
external ChatGPT review); Faceless Studio stays v1.5. Templates gallery is IN
v1.4 but sequenced AFTER the generator core (C4b) — templates built on
generated backgrounds land once, premium-looking, instead of being rebuilt
twice. v1.4 ships as ONE full release at C7 (Yasser 2026-11-11: "we need 1.4
to be massive hit"; interim tag only if decided later).

Every commit: unit tests first where math is involved (RED before fix), then
fix, then `scripts/smoke_test.py` + CLI render + ffprobe gate. Golden frames
only re-baselined for commits that intentionally change pixels (C3, C5).
Nothing pushed or tagged without Yasser's word.

## Locked decisions (agreed 2026-11-11)

| # | Decision | Ruling |
|---|----------|--------|
| D1 | Generator vs image | Both first-class; same compositor; generator-only project valid end-to-end, no dummy image |
| D2 | Preset palettes | **Fixed designed palettes** — presets do NOT follow the project color preset. The designed look is the point (and the later pack-selling angle) |
| D3 | UI surface | Preset dropdown + Motion: Subtle/Normal only. No layer editor, no sliders. Config supports more params internally |
| D4 | Motion model | ONE shared driver per shot; pattern layer = 0.6x multiplier of it; vignette stationary; grain = one static noise texture drifting with the driver (deterministic seed by frame idx, temporally coherent — no fresh noise per frame) |
| D5 | Subtle/Normal semantics | **Amplitude multiplier on the shared driver** (Subtle ≈ 0.4x movement). Speed of the shot never changes |
| D6 | Performance | One controlled benchmark at FHD and 2K (the agreed tiers); cache coordinate grids + static pattern layers; no per-frame full allocations. Note: current Ken Burns path (overscanned base + LANCZOS every frame) is the cost ceiling — generators should be cheaper, benchmark proves it |
| D7 | Effects scope | Grain, vignette in all presets; halftone/dots inside Signal Field; scanlines considered for Grid Pulse; NO general effects framework |

## Commit sequence (each lands green on its own)

### C1 — Resolution selector: 720p / FHD / 2K (previously agreed tiers)
Verified today: the engine ALREADY honors `width`/`height` from project JSON
(engine.py:151-152), and checks.py has a resolution gate. What's missing is
the app/UI surface + font-scale sanity at extremes. Tiers locked to what was
agreed before — 720p, FHD (1080x1920), 2K (1440x2560). No 4K tier (Yasser
2026-11-11); the RAM stress case is covered by 2K.
- app.py: expose resolution choice on project create/render (writes width/height).
- tests/test_resolution_matrix.py (new): render one tiny shot at 720x1280,
  1080x1920, 1440x2560 in-process — layout fits, no overflow flags, encodes.
- Risk to verify first: font sizes are px constants; confirm readability
  ratio at 720p (likely scale fonts by min(W,H)/1080 if needed — measure, don't guess).
- CLI: `--scale` flag as power-user path.

### C2 — Voice speed control (piper length_scale)
Verified today: `piper_line()` (core/audio.py:261) shells to piper with no
speed arg; piper supports `--length-scale`.
- project key `vo_speed` (0.8/1.0/1.25 = Slow/Normal/Fast); threads through
  piper_line + vo_duration cache key (cache key MUST include speed).
- vo_plan re-times lines after synth (durations come from actual wav, so
  timing follows automatically — verify with a unit test on the plan math first).
- UI: one dropdown in the voice panel.

### C3 — Background generator engine core (biggest commit)
The seam already exists: `render_layer()` dispatches per-shot `fill` =
image/solid/grid/collage (engine.py:526-531). Generator = new fill branch,
NOT an architecture change. Previews ride for free because storyboard/anim/
style previews call the same Engine.
- core/generators.py (new): 6 presets as pure functions of
  (W, H, driver_offset, motion_amp) -> RGB; cached coordinate grids + static
  pattern layers per (preset, W, H); shared-driver transform with per-layer
  multipliers (D4); drifting grain.
- engine.py: `fill: "gen:<name>"` branch in render_layer; validate_project
  whitelist extension (reject unknown gen names at load).
- tests/test_generators.py FIRST (RED): determinism (same seed idx -> identical
  array), driver continuity, palette freeze per preset, grain coherence.
- Golden: new corpus shots for the 6 presets (additive only — existing golden
  must stay byte-identical; that IS the backward-compat proof).

### C4 — Mixed + generator-only projects end-to-end
- validate_project already tolerates missing `image` when fill is set — verify,
  extend if needed (the bad_images check at engine.py:234 keys on `s.get("image")`).
- App: background source toggle (Image | Generator) in shot editor; preset
  dropdown + Motion Subtle/Normal (D3). Storyboard/style previews need zero
  extra work (same Engine) — but the smoke suite gets explicit checks for them.
- Integration gate = the external review's 9-point boundary, mapped onto our
  harness: image-only golden unchanged; generator-only CLI render + ffprobe;
  mixed project render; previews via TestClient; determinism double-render;
  parallel (--jobs) consistency; old JSONs load untouched.

### C4b — Templates gallery (built ON the generator, lands once)
- templates/ dir + a small curated set (quality over quantity — external
  review's own advice): each template = preset + shot skeleton + background
  source (generated or image slot for the user's own media).
- app.py: gallery tab (reuses the same per-preset preview plumbing as C3's
  generator previews; _gallery_task lock already exists from the fix pass).
- CC0 music beds: 2-3 tracks max in `music/` with ATTRIBUTIONS.md entries —
  only if genuinely CC0-clean sources verified; otherwise ship without and
  keep procedural beds (synthwave/pulse) as the default. Never guess licenses.
- smoke: one template -> full CLI render + ffprobe gate.

### C5 — Share export: GIF / WebP animation
- render_cli.py: `--gif` / `--webp` (encode from the existing frame dir or
  re-use encoded mp4 via ffmpeg palette-split for quality).
- app.py: format selector on download; sizes capped (GIF is a share teaser,
  not the master — cap duration/size, document it).
- smoke: one tiny GIF + WebP render, ffprobe both.

## Open risks (flag now, not mid-build)
1. **720p legibility**: px-constant fonts may look oversized/cramped at 720 —
   C1 starts with a measurement test before any scaling code.
2. **2K memory**: bases dict holds every image overscanned in RAM; at 2K that's
   ~1.8x per image vs FHD. Mitigation if the benchmark bites: store bases at
   FHD and upscale, or lazy-load per shot. Decide from measured numbers (D6).
3. **GIF size**: 12s @ 1080 GIF is absurd; cap teaser format (e.g. 640px, 6s) —
   confirm the cap with Yasser when C5 starts.
