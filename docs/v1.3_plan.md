## Commit sequence (each commit independently green on local smoke + CI)

### C0 — nb_frames smoke assertion (first code commit, one-liner)
- Smoke test gains: ffprobe `-count_frames` → assert `nb_read_frames == N`
  (target*fps), not just duration ±0.15s. The duration gate alone would hide a
  dropped/duplicated frame class of bug.
- NOTE: the external review claimed ffmpeg image2 defaults `start_number=1` and
  that frame 0 is silently dropped from every encode. **Verified false on our
  own ffmpeg**: help says `(default 0)`, a 6-PNG probe sequence encoded with the
  exact repo command shape yields all 6 frames, and promo_v121.mp4 probes at
  nb_frames=360 for N=360. No `-start_number 0` flag is needed or added. The
  assertion above is still worth shipping as a guard.

### C1 — Golden-frame harness (zero engine changes)
- `scripts/golden_frames.py`: renders a fixed corpus deterministically and
  writes SHA-256 per frame to `tests/golden/hashes.json` (top-level `tests/`,
  NOT under gitignored `output/`).
- Corpus: samples/promo_v12.json (N=360, all frames) + **ONE synthetic
  multi-shot project carrying all 11 caption kinds in separate shots** (one
  Engine build instead of 11 — engine construction with font load + LANCZOS
  pre-scale is the dominant cost), sampled at fixed progress points
  (at+0.15s, at+0.6s, settled), rendered in leebdark + one second preset × all
  three formats (9:16, 1:1, 16:9).
- **Scope decision: baseline covers full-res renders only.** C5 style previews
  are explicitly OUT of hash scope (no `scale` dimension in the corpus).
- Determinism is ASSERTED, not TODO'd: harness checks the render path uses only
  seeded RNG (`random.Random(idx*7919)` grain etc.) and no wall-clock calls
  (verified clean: time.time() only in queue job metadata, outside rendering).
- End-to-end leg: harness also runs ONE real encode (frames → ffmpeg → ffprobe
  nb_frames) so the sequence-read layer is exercised, which compose_frame-level
  hashing cannot catch.
- `scripts/golden_check.py` = local gate; CI placement: **full corpus on the
  Windows weekly/dispatch gate** (the shipping OS), **sampled subset (~every
  10th promo frame + one kind per format) on the linux push gate** to keep
  push latency low.
- Escape hatch: `--update` regenerates the baseline (only for intentional
  visual changes; commit message must say so).
- Why first: every later refactor must be provably pixel-identical or an
  announced diff. Safety net for C2–C4.

### C2 — Preamble ordering fix (real bug, confirmed twice)
The panel_* −0.45s clock shift runs at engine.py:~528 **after** the transition
freeze (`prog = min(prog, ...)` at :~516), then is re-applied at :~529-531. Net
effect on outgoing layers inside a transition window: the early-start benefit
is cancelled — panel text can freeze near prog≈0 and fade out unseen.
Fix: apply `at -= 0.45` (kind preamble) **before** the freeze block, delete the
re-apply patch. One small diff.
- **Blast radius is broader than "transition-window frames"** (review catch,
  confirmed): prog for panels is currently computed from unshifted at (~:509)
  while slide/gating/word clocks use shifted at — so panel ENTRY TIMING on
  ordinary non-transition frames changes too. Expect golden diffs across many
  frames; the commit message says this BEFORE the baseline regeneration, so the
  diff doesn't look alarming.
- checks.py drift (panel done_at from raw `at`, checker ~0.45s stricter than
  renderer) is NOT patched here — C4 kills it at the root. No partial fixes.

### C3a — core/captions.py: verbatim move behind per-kind functions
Split render_layer's ~250-line kind if/elif chain into one class per kind,
**zero helper movement, zero behavior change**:

```python
class CaptionKind:
    def preamble(self, at): return at        # clock shifts (panel -0.45)
    def draw(self, dr, style, fc, L): ...    # verbatim body today
```

- `style` = colors/fonts/LY/P groups; `fc` (frame ctx) = lt, shot_t, at, prog,
  slide, a_gate — explicit groups, NOT one god-ctx holding all Engine state.
- Kinds that derive sub-clocks (panel_*, cap_lines, terminal, chips) receive
  `at` and `shot_t` in fc so they can recompute their staggers exactly as today.
- Shared gates (prog clock, fade/a_gate, slide) stay in render_layer.
- C1 proves pixel identity before/after (minus C2's announced diffs).

### C3b — measure side + metrics cache (separate provable commit)
- Move fit_title / fit_panel_lines / wrap_words layout math into per-kind
  `measure()` returning Metrics; draw consumes cached metrics.
- **Engine-level metrics cache keyed by (shot index, caption index)**,
  invalidated on project edit — removes today's per-frame refit cost
  (fit_title's shrink-and-rewrap loop runs ~fps*t times per shot).
- C1 again proves pixel identity: caching must not change any hash.

### C4 — checks.py on Metrics (single source of truth)
Today checks.py re-derives wrap results, line counts, `done_at` formulas by
mirroring engine internals (its own comment admits "mirrors render_layer
exactly" — and it already drifted: the 0.45s panel preamble is missing there).
Rewrite check_project to call each kind's `measure()` and assert on returned
Metrics: wrapped lines, box sizes, completion times, safe-width margins.
- **Semantics decision (agreed): Metrics.done_at = SETTLE TIME** (last element
  reaches progress 1), same meaning as today's timing flags. Storyboard strip
  keeps its fixed 0.75*shot_t sampling in v1.3 — no visual change under a
  refactor label; revisit sampling vs done_at in v1.4 if wanted.
- Smoke gains: checks-on-samples stay green; a planted bad project flags
  identically to today (existing timing/overflow expectations preserved).

### C5 — Style previews (F slot, started per Yasser's decision)
`GET /api/style_preview/{preset}` renders a short mini-loop per preset, shown
as picker thumbnails in ui/index.html. Shape per review merge:
- **Half-res goes THROUGH build_layout with real half dimensions** (S scaling
  from actual W,H), not downscale-after-render — proves what the preset looks
  like at its true layout.
- **Format: animated webp (or static early+settled frame pair) — NOT GIF.**
  Cyan-on-black gradients band visibly in GIF's 256-color palette.
- **Queue shape: bounded sub-job on the existing parallel pool, not a "low
  priority" queue class** — with one worker thread, a 60-frame preview render
  would block the user's real render; previews must never sit in front of
  actual jobs. Cap concurrent previews.
- Out of golden-hash scope (see C1).
